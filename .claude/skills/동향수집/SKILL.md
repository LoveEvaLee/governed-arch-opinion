# ① 동향 수집

## 하는 일

1. 영역을 받으면 공개 자료(클라우드 사업자 공식 문서 · 레퍼런스 아키텍처 · 사례 발표 · 기술 블로그)에서 선택지와 사례를 모은다
2. 건마다 출처 · 날짜 · 신뢰도 등급을 붙인다
3. 쏟아지는 자료를 그대로 넘기지 않고, 선택지별 대표 근거 몇 건으로 줄인다
4. `refs/<영역>.md`에 같은 항목으로 정리한다 — 출처 / 어떤 상황에 쓰는 구조인지 / 구성 요소 / 전제 조건

## 신뢰도 등급

| 등급 | 출처 |
|---|---|
| A | 클라우드 사업자·프로젝트 공식 문서, 공식 레퍼런스 아키텍처 |
| B | 공개된 기업 사례 발표, 동료 심사 자료 |
| C | 실무자 기술 블로그 (작성자·날짜 확인 가능) |
| D | 출처·날짜 불명, 마케팅 자료 |

등급 기준은 초안. 쓰면서 고친다.

## 입력

영역 이름. 첫 버전은 ETL·오케스트레이션, AI/에이전트 플랫폼.

## 출력

- `refs/<영역>.md`
- `refs/비교표.md` 갱신 — 갈래별 공통 패턴과 갈리는 지점

## 하지 않을 것

- 회사 정보를 검색어에 넣기 — 이 에이전트는 공개 정보만 다룬다
- 날짜 없는 자료를 최신 근거로 쓰기
- 출처 없는 주장을 refs에 남기기

## 현재 상태

뼈대만. `refs/` 세 갈래(랜딩존 · 데이터플랫폼 · 하이브리드연계)는 이전 범위에서 수집한 것이 있다.

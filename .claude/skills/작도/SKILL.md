# ⑥ 작도

## 하는 일

1. 받은 구조안(구성요소 종류와 연결 관계)을 `layouts/표기규칙.md` 표기로 옮긴다
2. 구성도는 `.drawio`(AWS 아이콘)로, 데이터·작업 흐름은 Mermaid로 그린다
3. 두 안을 그릴 때는 같은 배치·같은 표기로 나란히 그려, 차이가 그림에서 바로 보이게 한다
4. 고정 구조(②)에서 벗어난 부분은 표기규칙의 강조 표기로 짚는다

## 왜 따로 두는가

③과 ④가 같은 표기로 그리게 하려고. 그리는 쪽이 하나여야 그림끼리 비교가 된다.

## 입력

- 구조안 텍스트 — ③의 우리 안, ④가 옮긴 운영사 안
- `layouts/표기규칙.md`
- ②의 고정 구조 요약 (회사 사례일 때)

## 출력

- 회사 사례 — `private/사례/<사례명>/구성도_<안이름>.drawio`, 흐름도는 같은 폴더 `.md` 안의 Mermaid
- 공개 예시 — `out/` (익명 기호만)
- PNG는 원본이 아니라 내보낸 사본이다.
- `.drawio`를 만들면 draw.io 명령줄로 같은 이름의 `.png`를 내보낸다
- 커밋 전에 `.drawio`를 요소마다 줄바꿈된 XML로 정리한다 (draw.io 앱에서 고친 뒤에도)

## 하지 않을 것

- 구조안에 없는 구성요소를 추론해서 그려 넣기 → 〔미정〕 표시
- 실제 시스템명·IP·호스트명·계정 ID를 공개 쪽 그림에 쓰기
- 어느 안이 나은지 그림에 결론 내기 — 판정은 ④⑤와 사람의 몫

## 현재 상태

표기규칙 보강(2026-10-09, 첫 시험 반영). 첫 시험은 에이전트 구성도(`out/에이전트_구성도.drawio`)였고, 거기서 나온 애매한 곳을 `layouts/표기규칙.md`에 반영했다.

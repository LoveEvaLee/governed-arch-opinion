# ① 동향 수집

## 하는 일

영역 하나를 받아, 그 영역의 선택지와 선택지별 근거를 공개 자료에서 모아 `refs/<영역>.md`에 쓴다. 쏟아지는 자료를 그대로 넘기지 않고 선택지마다 대표 근거 몇 건으로 줄인다. 판정(상 · 중 · 하)은 하지 않는다 — 근거를 ③④⑤에 넘기는 데까지다.

## 영역과 파일

AWS Control Tower 랜딩존 기준 11개. 한 번에 영역 하나만 한다(diff로 읽을 수 있는 크기).

| # | 영역 | 파일 | 비고 |
|---|---|---|---|
| 1 | ETL · 오케스트레이션 | `refs/ETL오케스트레이션.md` | 첫 버전 |
| 2 | AI · 에이전트 플랫폼 | `refs/AI플랫폼.md` | 첫 버전 |
| 3 | 데이터 플랫폼 | `refs/데이터플랫폼.md` | 기존 파일 보강 |
| 4 | 데이터 거버넌스 | `refs/데이터거버넌스.md` | 첫 버전 |
| 5 | 계정 · OU 구조 | `refs/랜딩존.md` | 기존 파일 보강 |
| 6 | 네트워크 | `refs/네트워크.md` | |
| 7 | 하이브리드 연계 | `refs/하이브리드연계.md` | 기존 파일 보강 |
| 8 | 보안 · ID | `refs/보안ID.md` | |
| 9 | 로깅 · 감사 · 모니터링 | `refs/로깅감사모니터링.md` | |
| 10 | 비용 관리 | `refs/비용관리.md` | |
| 11 | 컴퓨트 · 컨테이너 | `refs/컴퓨트컨테이너.md` | |

기존 파일은 새로 만들지 않고 아래 형식으로 바꿔 채운다.

## 입력

- 영역 이름 (필수)
- 꼭 넣을 선택지 이름 (선택) — 예: 운영사가 제안한 도구. **이름만 받는다.** 왜 넣는지(회사 사정)는 받지 않고 검색어에도 쓰지 않는다
- `private/`는 읽지 않는다. 이 에이전트는 공개 정보만 다룬다

## 순서

1. **선택지 목록부터 정한다.** AWS 관리형을 기준으로, 비교용으로 오픈소스(직접 운영 · 관리형 둘 다 있으면 둘 다)와 타사 클라우드 대응 서비스를 넣는다. 영역당 3~6개. 목록과 고른 이유를 먼저 보여 주고, 사람이 "시작해"라고 하면 수집한다
2. **선택지마다 근거를 모은다.** 공식 문서 → 공식 레퍼런스 아키텍처 → 공개 기업 사례 → 실무자 블로그 순으로 찾는다
3. **건마다 등급 · 날짜를 붙인다** (아래 기준)
4. **거른다** (아래 기준)
5. **`refs/<영역>.md`에 쓰고 `refs/비교표.md`를 갱신한다**
6. **센 표를 보여 준다** (아래 「끝나면」)

## 신뢰도 등급

등급은 출처가 아니라 **주장 단위**로 붙인다. 같은 문서라도 무엇을 근거로 쓰느냐에 따라 등급이 다르다.

| 등급 | 출처 | 예 |
|---|---|---|
| A | 클라우드 사업자 · 프로젝트 공식 문서, 공식 레퍼런스 아키텍처, 공식 릴리스 노트 · 저장소 | 서비스 문서의 기능 · 한도 · 요금표, 프로젝트의 릴리스 이력 |
| B | 공개된 기업 사례 발표, 동료 심사 자료 | 컨퍼런스 발표의 도입 사례, 사업자 블로그에 실린 고객 사례(회사명 공개) |
| C | 실무자 기술 블로그 (작성자 · 날짜 확인 가능) | 개인 · 기업 기술 블로그의 운영 후기, 비교 실험 |
| D | 출처 · 날짜 불명, 마케팅 자료 | 작성자 없는 글, 제품 홍보 페이지 |

**주장 단위 규칙**

- 사업자 · 벤더가 **자기 제품이 낫다**고 하는 비교 주장은 공식 문서에 있어도 D다. 같은 문서의 기능 · 한도 · 요금 사실은 A다
- 유료 애널리스트 리포트를 인용한 기사 · 요약은 C다 (원문 확인 불가)
- 커뮤니티 활동(릴리스 주기 · 기여자 수 · 이슈 응답)은 공식 저장소에서 직접 본 값이면 A, 남이 정리한 값이면 그 글의 등급을 따른다
- 애매하면 낮은 쪽을 준다. 결론을 바꾸려고 등급을 올리지 않는다

등급 기준은 초안이다. 고칠 때는 `rubric/평가축.md` 「근거 등급과 판정의 상한」과 함께 본다.

## 날짜 기준

- 건마다 **발행일(또는 최종 갱신일)과 확인일(내가 연 날)** 둘 다 적는다
- 날짜를 찾을 수 없으면 D로 내린다
- 발행 · 갱신이 **24개월보다 오래된 자료**는 「오래됨」을 붙인다. 구조 설명의 근거로는 쓸 수 있지만, 동향(성숙도 · 방향)의 근거로는 쓰지 않는다
- 서비스 상태(정식 출시 · 프리뷰 · 지원 종료 예고)는 공식 문서에서 확인일 기준으로 적는다

## 거르는 기준

- 선택지당 **대표 근거 3건까지.** A 1건 이상을 목표로 하고, 없으면 「A 근거 없음」을 적는다
- 같은 내용이면 등급이 높은 쪽, 같은 등급이면 최신 쪽을 남긴다
- 버린 건은 적지 않되, 버린 건수만 선택지별로 센다
- 검색은 **선택지당 3회, 영역 합계 20회**까지. 넘어야 할 것 같으면 멈추고 무엇이 부족한지 보고한다
- URL은 실제로 열어 본 것만 쓴다. 열지 못한 URL은 쓰지 않는다

## 출력 — `refs/<영역>.md`

```
# 참조 — <영역>

수집일: YYYY-MM-DD · 검색 N회 · 버린 건 N건

## 선택지 요약

| 선택지 | 종류 (관리형 · 직접 운영 · 타사) | 상태 (GA · 프리뷰 · 지원 종료 예고) | 근거 건수 (A/B/C/D) |
|---|---|---|---|

## <선택지 이름>

### 근거 1 — <한 줄 제목>

| 항목 | 내용 |
|---|---|
| 출처 | 문서명 · 발행처 · URL |
| 날짜 | 발행(갱신) YYYY-MM-DD · 확인 YYYY-MM-DD · 「오래됨」 여부 |
| 등급 | A~D — 이 근거로 쓰는 주장 한 줄 |
| 적용 상황 | 어떤 상황에 쓰는 구조인지 |
| 구성 요소 | |
| 전제 조건 | 이 구조가 성립하려면 무엇이 있어야 하는지 |
| 걸리는 평가 축 | 이 근거가 받쳐 주는 축과 「보는 항목」 (예: 동향 적합성 — 종속성) |

### 비어 있는 것
이 선택지에서 근거를 못 찾은 「보는 항목」. ③④⑤가 〔미정〕의 이유로 쓴다.
```

확인되지 않은 칸은 추론해서 채우지 않고 〔미정〕. 원문은 길게 옮기지 않고 요지만 쓴다.

## 출력 — `refs/비교표.md` 갱신

- 「영역별 수집 현황」 표에 영역 · 선택지 수 · 근거 건수 · 등급 분포 · 수집일을 적는다
- 「공통 패턴」 · 「갈리는 지점」 · 「표기 차이」에 이번 영역에서 나온 것을 덧붙인다. 「표기 차이」는 `layouts/표기규칙.md`에 넘길 후보다

## 끝나면 — 센 표를 보여 준다

결과 파일을 열어 센다. 에이전트의 요약이 아니라 파일 기준이다.

| 항목 | 값 |
|---|---|
| 선택지 수 | |
| 근거 건수 (A / B / C / D) | |
| 날짜 빠진 건 | 0이어야 함 |
| 등급 빠진 건 | 0이어야 함 |
| 「오래됨」 건 | |
| A 근거 없는 선택지 | |
| 검색 횟수 · 버린 건 | |

## 하지 않을 것

- 회사 정보를 검색어에 넣기, `private/` 읽기
- 판정(상 · 중 · 하) 내기 — ③④⑤의 일
- 날짜 없는 자료를 최신 근거로 쓰기
- 벤더의 자기 우월 주장을 사실로 옮기기
- 출처 없는 주장을 refs에 남기기
- 한 번에 영역 두 개 이상 하기

## 현재 상태

보강(2026-10-11). 첫 실행은 3-1 ETL · 오케스트레이션. `refs/` 기존 세 파일(랜딩존 · 데이터플랫폼 · 하이브리드연계)은 틀만 있고 수집 0건.

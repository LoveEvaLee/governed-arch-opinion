# 표기 규칙 (초안 — 쓰면서 고친다)

**목적.** 상대 그림을 옮겨 담을 그릇. 참조 아키텍처도 출처마다 표기가 다르고 인프라 담당 PPT도 담당자마다 달라서, 그릇이 없으면 비교가 안 된다.

**원칙.** 표기는 1종으로 고정한다. 옮겨 담는 쪽이 규칙에 맞추지, 규칙이 그림마다 늘어나지 않는다.

## 그림 종류와 형식

| 종류 | 형식 | 언제 |
|---|---|---|
| 구성도 | `.drawio` | 계정·네트워크·서비스 배치 — 인프라 구조 |
| 흐름도 | Mermaid (`.md` 안) | 데이터 흐름 · 작업 순서 |
| 에이전트·작업 구성도 | `.drawio` | 에이전트·역할 사이의 입력과 출력 — 인프라가 아닌 구조 |

PNG는 내보내기용으로만 만든다. 원본은 항상 `.drawio` 또는 Mermaid다.

## 계층 이름 (구성도)

바깥에서 안쪽 순서로 그린다. AWS Control Tower 랜딩존 기준.

조직 → OU → 계정 → 리전 → VPC → 가용 영역(AZ) → 서브넷(공개 · 비공개) → 서비스

- 온프레미스는 AWS 바깥에 별도 상자로 둔다
- 계층 상자는 draw.io의 AWS 그룹 모양(aws4)을 쓴다

## 요소 표기

- 서비스는 AWS 공식 아키텍처 아이콘(draw.io aws4 라이브러리)을 쓴다
- AWS 밖 도구(오픈소스 등)는 흰 바탕 사각형 + 도구 이름으로 쓴다. 로고를 임의로 그리지 않는다
- 이름표는 "역할(서비스 종류)"로 쓴다. 예: `적재(오브젝트 스토리지)`. 실제 시스템명은 쓰지 않는다
- 에이전트·작업 구성도는 draw.io 기본 도형(둥근 사각형)을 쓰고, 이름표는 "번호 이름 — 하는 일 한 줄"로 쓴다

## 연결선

| 선 | 뜻 |
|---|---|
| 실선 화살표 | 데이터 흐름 (방향 = 데이터가 가는 쪽) |
| 점선 화살표 | 제어 · 호출 (작업 실행, API 호출) |
| 굵은 실선 | 네트워크 연결 (전용선 · VPN · 피어링) |
| 회색 점선 | 관리 · 감사 (로그 수집, 권한) |

## 경계선과 강조

| 표시 | 뜻 |
|---|---|
| 회색 채움 | ②의 고정 구조 — 손대지 않는 부분 |
| 파란 테두리 | 이번 안이 추가하는 부분 |
| 주황 굵은 테두리 | 두 안 비교에서 서로 다른 부분 (④·⑥이 짚는 곳) |
| 점선 상자 + 〔미정〕 | 값이나 구성이 확인되지 않은 자리 |

색만으로 구분하지 않는다. 강조에는 테두리 모양(굵기 · 점선)을 같이 쓴다.

## 두 안 나란히 그리기

- 같은 캔버스에 왼쪽 운영사 안, 오른쪽 우리 안
- 고정 구조 부분은 두 쪽이 같은 위치 · 같은 크기
- 차이는 주황 테두리로만 표시하고, 어느 쪽이 나은지는 그림에 쓰지 않는다

## 흐름도 (Mermaid)

- `flowchart LR`(왼쪽 → 오른쪽)을 기본으로 한다
- 노드 이름은 역할로 쓴다. 연결선 뜻은 구성도와 같다(실선 = 데이터, 점선 = 제어)

## 미정 표시

값이 확인되지 않은 자리는 〔미정〕으로 남긴다. 기준선에 없는 내용을 추론해서 채우지 않는다.

## 이 파일에 쓰면 안 되는 것

실제 시스템명·경로를 예시로 넣지 않는다. 예시가 필요하면 익명 기호(A·B·가·나)를 쓴다.

# ② 맥락

## 하는 일

회사별 조건을 한곳에 보유하고, 다른 에이전트가 같은 조건을 쓰게 한다.

| 항목 | 내용 |
|---|---|
| 고정 구조 | 전사 클라우드 표준 구조 — 이 위에 얹는다 |
| 정책 | 데이터 분류 · 접근 · 반출 · 보존 기준 |
| 제약 | 실행 환경, 입력 허용 범위, 조직 사정 |
| 가중치 | 평가 축 7개의 회사별 가중치 (`rubric/평가축.md` 참조) |
| 연계 대상 | 공통 플랫폼 등 반드시 맞춰야 할 외부 조건 |

## 왜 따로 서는가 — 되돌리지 않는 판단

회사 맥락을 공개 에이전트와 떼어 놓아야 어느 회사에서나 쓸 수 있다. 공개되는 것은 이 지침뿐이고, 내용은 `private/`(커밋 제외)에만 있다.

## 입력

`private/` — `private/맥락.md`, `private/가중치.md`, `private/기준선_구조.md`

## 출력

③④⑤가 읽는 조건 요약. 비어 있는 항목은 〔미정〕으로 넘긴다.

## 하지 않을 것

- 회사 정보를 공개 저장소에 쓰기
- 실제 값(IP · 호스트명 · 계정 ID) 보유 — 구성요소 종류와 연결 관계 수준까지
- 비어 있는 조건을 추론해서 채우기

## 현재 상태

뼈대만. 비공개 쪽 `맥락.md` · `가중치.md` 미작성.
